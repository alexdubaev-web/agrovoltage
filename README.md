# АГРОВОЛЬТАЖ — сайт

Статический сайт на Eleventy 3 с контентом в Markdown/JSON, редактор — Sveltia CMS, заявки — PHP-обработчик.

## Что нужно

- Node.js 22 или новее
- PHP 8.2 или новее (`php` в PATH) — для форм заявок в `npm run dev` и для тестов обработчика

## Команды

| Команда | Что делает |
|---|---|
| `npm install` | ставит зависимости |
| `npm run dev` | сайт на http://localhost:8080 с пересборкой при изменениях; PHP-файлы из `public/api/` выполняются на том же адресе |
| `npm run build` | проверяет данные и собирает сайт в `dist/` |
| `npm run validate` | только проверка данных против `schemas/` |
| `npm test` | сборка и все проверки (`node --test "tests/*.test.mjs"`) |

Один файл тестов: `node --test tests/build.test.mjs`.

Если в данных ошибка, сборка останавливается и пишет, например:
`src/content/services/remont.md: поле title — обязательное поле не заполнено`. Папка `dist/` при этом не создаётся.

## Настройки окружения

Скопируйте `.env.example` в `.env` и заполните нужное. `.env` не коммитится.

- `SITE_URL` — адрес сайта без слеша в конце. По умолчанию `http://localhost:8080`.
- `INDEXABLE=true` открывает сайт для поисковиков, но только вместе с `SITE_URL`, начинающимся с `https://`. Иначе на всех страницах `noindex,nofollow`, а в `robots.txt` — `Disallow: /`.
- `SMTP_*`, `MAIL_FROM`, `MAIL_TO`, `MAX_BOT_TOKEN`, `MAX_CHAT_ID` — каналы доставки заявок. Пока они пустые, заявки только пишутся в журнал.

## Редактирование через Sveltia (локально)

1. Запустите `npm run dev`.
2. Откройте http://localhost:8080/admin/ в Chrome или Edge (другие браузеры не дают доступ к папке).
3. Нажмите «Работать с локальным репозиторием» и выберите корневую папку проекта.
4. Правьте услуги, товары, статьи, регионы, страницы и настройки. Sveltia сохраняет изменения прямо в файлы `src/content/` и `src/_data/`, сайт пересобирается сам.
5. Изменения попадают в git как обычные правки файлов: проверьте и закоммитьте их.

Картинки, загруженные в Sveltia, лежат в `src/assets/uploads/` и доступны по адресу `/assets/uploads/…`. На сайте они превращаются в AVIF и WebP нужных размеров.

После публикации сайта Sveltia работает через GitHub (репозиторий `alexdubaev-web/agrovoltage`, ветка `main`): вход кнопкой «Войти через GitHub» или токеном доступа.

## Где что лежит

| Путь | Что там |
|---|---|
| `src/content/` | услуги, категории, товары, статьи, регионы, страницы |
| `src/_data/settings.json` | контакты, реквизиты, SEO по умолчанию, ID Метрики |
| `src/_data/models.json` | модели и серии John Deere |
| `schemas/` | JSON Schema для каждой коллекции, ими проверяются данные |
| `src/admin/` | Sveltia: `index.html` и `config.yml` |
| `src/_includes/` | layout и общие части страниц |
| `src/assets/` | стили, шрифты, скрипты, логотип |
| `lib/` | загрузка контента, адреса, JSON-LD, картинки, сборка CSS/JS |
| `public/` | копируется в корень сайта как есть (`.htaccess`, `api/`) |
| `dist/` | готовый сайт, веб-корень хостинга |

Значения в квадратных скобках, например `[АДРЕС — впиши]`, — заглушки. Их нужно заменить в «Настройках» Sveltia.

## Логотип и иконки
