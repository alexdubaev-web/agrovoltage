# Спецификация: сайт АГРОВОЛЬТАЖ

## Задача

Сервису АГРОВОЛЬТАЖ нужен свой сайт. Владельцы сельхозтехники, в основном John Deere, в Ставропольском и Краснодарском крае должны находить сервис в Яндексе и в нейропоиске, понимать, что здесь чинят электрику, проводку, электрооборудование и кондиционеры, быстро оставлять заявку или заказывать запчасти. Владелец сайта сам меняет услуги, товары, статьи и контакты через Sveltia, без программиста. Хостинга и домена пока нет, поэтому всё собирается и проверяется локально.

## Решение

Быстрый лёгкий сайт из готовых HTML-страниц:
- главная;
- услуги со страницей на каждую услугу, построенной по образцу эталона: признаки → диагностика → работы → модели → вопросы-ответы → цены с кнопкой записи;
- каталог запчастей с категориями, поиском и корзиной: заказ оформляется как заявка без онлайн-оплаты;
- статьи;
- доставка, контакты, о компании, страницы регионов;
- политика и согласие на обработку ПД.

Заявки, обратная связь и заказы приходят на почту и в мессенджер MAX. Пока ключи не вписаны, заявки пишутся в локальный файл, и это видно в логе. Всё содержимое лежит в файлах Markdown/JSON внутри репозитория и редактируется в Sveltia по адресу `/admin/`. Локально Sveltia работает с папкой проекта, после выкладки — через GitHub. SEO под Яндекс и GEO: разметка schema.org, sitemap, robots с Clean-param, страницы регионов, `llms.txt`. Индексация закрыта, пока явно не включена.

## Решения по реализации

- **Генератор: Eleventy 3 (Node ≥ 22) с шаблонами Nunjucks.** Он читает Markdown/JSON, которые пишет Sveltia, по умолчанию не добавляет JS, а код шаблонов остаётся читаемым. Это ответ на главный минус cmteh: там вёрстка и данные склеены в одну строку.
- **Изображения: `@11ty/eleventy-img`** превращает исходники в AVIF и WebP нескольких размеров. Владелец загружает обычные JPG/PNG.
- **Клиентский JS: vanilla ES-модули** (корзина, формы, меню, поиск, согласие), без библиотек. Сборщик не нужен: два-три файла, минификация через esbuild на сборке.
- **CSS:** один файл с токенами на CSS-переменных и зелёной палитрой логотипа. Шрифт Manrope (OFL, кириллица) самохостингом.
- **CMS: Sveltia** — `/admin/index.html` грузит Sveltia с CDN (версия закреплена), `admin/config.yml` описывает коллекции. Backend `github` (репозиторий alexdubaev-web/agrovoltage, ветка main), локально — режим локального репозитория. Почему: бесплатно, без сервера, данные остаются в git.
- **Данные:** `src/content/` — `services/*.md`, `products/*.md`, `categories/*.json`, `articles/*.md`, `regions/*.md`, `pages/*.md`; `src/_data/settings.json` (контакты, реквизиты, SEO, ID Метрики), `src/_data/models.json` (модели John Deere). Перед рендером сборка проверяет данные валидатором на JSON Schema.
- **Формы: PHP 8.2+** (`public/api/lead.php`, `public/api/token.php`), код в `backend/` вне веб-корня. Причина: целевой хостинг — обычный российский PHP-хостинг, туда нельзя поставить Node. Почта через PHPMailer (вендорен), MAX через HTTP Bot API (`https://platform-api2.max.ru`, адрес в `MAX_API_URL` — D01: план предполагал platform-api.max.ru, документация на T04 показала platform-api2). Секреты только в `.env` по именам из `.env.example`.
- **Аналитика: Яндекс Метрика** после согласия. Ключ согласия хранится в localStorage 180 дней.
- **Тесты:** `node --test` по собранному `dist/` (мета, JSON-LD парсится и содержит нужные типы, sitemap, robots, noindex по умолчанию, бюджет размеров, отсутствие битых внутренних ссылок), юнит-тесты корзины (jsdom), PHP-тесты обработчика (встроенный сервер, режим «только журнал»). `npm test` запускает всё.
- **CI:** GitHub Actions `build.yml` — установка, сборка, тесты. Деплоя нет (R29i).

## Вне рамок

| Требование | Почему не сейчас |
|---|---|
| Онлайн-оплата | пользователь согласился на корзину как заявку (бриф, «3. Согласен») |
| Выкладка на хостинг, домен | хостинга и домена нет — «давай локально пока»; при появлении хостинга добавляется шаг деплоя в CI |
| Программное отключение DPF/EGR/AdBlue | есть у эталона, но в брифе нет и это юридически рискованно |
| Личный кабинет, история заказов | в брифе нет |
