## Что должно заработать

Любая форма `data-lead-form` на сайте отправляет заявку: звонок, заявка на услугу, заказ из корзины. PHP-обработчик проверяет данные, отсекает спам и записывает заявку в журнал. Затем отправляет её на почту и в MAX и отвечает номером заявки.

Пока ключей нет, обработчик работает в режиме «только журнал», и это видно в логе. Ошибки показываются по-русски у полей. Баннер согласия включает Метрику, только если ID задан. На мобильных есть плавающая кнопка «звонок / MAX».

## Критерии приёмки

- [ ] `GET /api/token.php` выдаёт токен. `POST /api/lead.php` без токена или с чужим токеном отвечает 403
- [ ] Валидные заявки трёх типов возвращают `{ok:true,id:"AGV-YYYYMMDD-NNNN"}` и пишутся в `storage/leads.jsonl` до отправки в каналы
- [ ] Невалидный телефон или пустое имя → 422 с русским текстом по полю. Без согласия → 422. Заполненная ловушка или заполнение быстрее 3 с → тихий отказ без записи в журнал
- [ ] Шестая заявка с одного IP за 15 минут → 429
- [ ] `MailChannel` (PHPMailer, SMTP из `.env`) и `MaxChannel` (HTTP Bot API MAX) реализуют `Channel::send`. Формат запроса MAX сверен с официальной документацией, ссылка — в комментарии. Канал без настроек пропускается с записью в `storage/app.log`. Сбой одного канала не мешает другому и не теряет заявку
- [ ] `php backend/console.php resend` повторно отправляет недоставленные записи
- [ ] `storage/` и `backend/` недоступны из веба: в `dist/` их нет, а `.htaccess` запрещает доступ на случай ошибки при выкладке
- [ ] `forms.js` показывает ошибки у полей и не стирает данные при ошибке. На время запроса повторная отправка заблокирована. При сбое — текст с телефоном +7 962 001 19 90. При успехе — номер заявки и событие `agv:lead-sent`, на которое подписывается корзина
- [ ] `consent.js`: без согласия Метрика не грузится. При согласии и заданном `yandexMetrikaId` — грузится. Цели: отправка формы, заказ, клик по `tel:`
- [ ] Плавающая кнопка «звонок / MAX» видна только на мобильной ширине
- [ ] Ни один секрет не попадает в репозиторий, `dist/` и логи
