# 0010. SEO-иерархия проверяется тестом по всему dist/

## Контекст

Заказчик требует заголовков «по всем правилам SEO». Страниц много, они генерируются из контента, который владелец правит сам.

## Решение

Один тест обходит весь собранный сайт (кроме админки) и проверяет: ровно один H1, уровни заголовков без пропусков, уникальные title (50–70 знаков) и description (120–160), alt у содержательных картинок. Отдельный тест проверяет те же длины на уровне данных и стоп-штампы в текстах.

## Почему

- Проверка выборки страниц отвергнута: ошибка чаще всего прячется в одной из многих страниц, сгенерированной из свежего контента.
- Проверка только шаблонов отвергнута: уникальность и длина зависят от текстов, а не от вёрстки.
- Ручная проверка перед выпуском отвергнута: владелец правит контент без разработчика, и поломку никто не заметит.
- Длины проверяются дважды (в данных и в dist/): в данных ошибка находится раньше и понятнее, в dist/ видно, что реально попало в разметку.

## Последствия

- Владелец, изменив title в Sveltia, может сломать `npm test`. Для него это неочевидно, правила придётся объяснить рядом с полями.
- Заглушки вида «[уточнить]» входят в длину и могут нарушить границы.
- Любая новая страница, включая 404 и служебные, обязана пройти правила сразу.
- Тест не проверяет смысл: заголовок нужной длины, но бессмысленный, он пропустит.
