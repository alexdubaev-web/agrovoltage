# 0008. Дизайн-система B и согласованные макеты как эталон

## Контекст

Заказчик оценил прежний сайт как «убожество» и попросил сначала макет, а реализацию только после согласования. Макеты варианта B согласованы 2026-11-04: «Согласую, верстай».

## Решение

Эталоном вида служат два согласованных макета: главная на десктопе и три мобильных экрана. Главная повторяет их порядок блоков, раскладку, палитру и шрифты. Внутренние страницы собираются из тех же компонентов, новых глобальных компонентов они не вводят. Система описана токенами: палитра, шрифты, шкала 16/18/22/28/40/56, скругления, сетка 8 px. Жёлтого цвета нет. Красный только для неисправности и ошибок форм, голубой только для климата. Отличия вёрстки от макета перечисляются в отчёте с причиной.

## Почему

- Вёрстка «по духу» отвергнута: прошлая попытка без макета закончилась отказом заказчика.
- Отдельный дизайн под каждую внутреннюю страницу отвергнут: даёт разнобой, на который заказчик уже жаловался. Один набор компонентов и одна система отступов держат цельность.
- Тема на готовом CSS-фреймворке отвергнута правилом проекта: без CSS-фреймворков, один `main.css`.
- Жёлтый исключён, чтобы сайт не повторял фирменные цвета бренда техники.

## Последствия

- Макеты — картинки: расхождения между ними и вёрсткой ловятся вручную, автоматической проверки нет.
- Макеты показывают только главную. У внутренних страниц эталона нет, они держатся на компонентах и описании системы.
- Лимиты веса (CSS до 40 КБ, JS до 30 КБ в gzip) ограничивают рост системы. Новый компонент придётся оплачивать удалением старого.
- Старые тесты, привязанные к прежней разметке, обновляются. Это допустимо, пока смысл проверки сохраняется.
