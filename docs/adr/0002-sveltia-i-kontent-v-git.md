# 0002. Sveltia и контент в git

## Контекст

Владелец сам меняет услуги, товары, статьи и контакты без программиста. Хостинга и сервера пока нет. Сайт хранится в репозитории alexdubaev-web/agrovoltage.

## Решение

Всё содержимое лежит в файлах Markdown/JSON внутри репозитория. Редактирует его Sveltia по адресу `/admin/`. Локально Sveltia работает с папкой проекта, после выкладки через GitHub. Перед сборкой данные проверяются по схемам, ошибка называет файл и поле по-русски.

## Почему

- Vibe-cms отвергнут: в нём нет каталога и форм, а работает он только на VDS с PostgreSQL и Docker. У проекта нет VDS, а целевой хостинг обычный PHP.
- Decap CMS отвергнут: развивается медленнее Sveltia.
- Sveltia бесплатный, не требует сервера, и данные остаются в git. Это совпадает с отсутствием хостинга.

## Последствия

- Локальный режим Sveltia работает только в Chrome и Edge. Это придётся объяснять владельцу в README.
- После выкладки редактирование зависит от GitHub и учётной записи владельца в нём.
- Sveltia подгружается с CDN. Версию нужно закреплять, иначе обновление CMS может сломать админку без нашего участия.
- Конфиг Sveltia и схемы данных нужно держать в точном соответствии. Любое новое поле правится в обоих местах.
