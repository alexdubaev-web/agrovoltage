# 0003. PHP-обработчик заявок с журналом до отправки

## Контекст

Заявки, обратная связь и заказы должны приходить на почту и в MAX. Целевой хостинг обычный российский PHP-хостинг, ключей к каналам пока нет.

## Решение

Заявки принимает PHP 8.2 и выше. Порядок такой: проверка, запись в журнал вне веб-корня, затем отправка в каналы, затем отметка статуса доставки. Почта и MAX независимы, сбой одного не теряет заявку. Без ключей работает режим «только журнал». Неотправленное переотправляется командой `resend`.

## Почему

- Серверный обработчик на Node отвергнут: на целевом хостинге Node поставить нельзя.
- Отправка сразу в каналы без журнала отвергнута: любой сбой почты или MAX терял бы заявку, а заявка здесь и есть выручка сервиса.
- Журнал до отправки даёт две вещи: ни одна заявка не пропадает, и без ключей сайт можно проверять целиком.
- Каналы сделаны за общим интерфейсом, поэтому третий канал добавляется без правки обработчика.

## Последствия

- В проекте два рантайма, Node для сборки и PHP для форм. Проверять нужно оба.
- Хостинг должен позволять писать в папку журнала и держать её вне веб-корня.
- Журнал содержит персональные данные (имя, телефон). Ему нужны права доступа, срок хранения и учёт в политике обработки ПД.
- Переотправка запускается вручную. Пока оператор не запустил `resend`, неотправленная заявка лежит только в журнале.
- Защита от спама ограничена: скрытое поле, токен, лимит по IP, минимальное время заполнения. Спам получает фиктивный успех и в журнал не попадает.
