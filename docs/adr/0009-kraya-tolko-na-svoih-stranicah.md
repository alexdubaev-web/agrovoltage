# 0009. Названия краёв только на своих страницах, в разметке остаются

## Контекст

Сервис работает в Ставропольском и Краснодарском крае. Заказчик: краёв «не надо тулить куда попало, это должно быть ньюансно а не на главной». При этом регион остаётся полезным сигналом для поисковиков.

## Решение

Названия краёв видны только на /regiony/, страницах краёв, /kontakty/ и /dostavka/. На главной, включая подвал, их нет. В подвале допустима ссылка «Где работаем» без перечисления. Для поисковиков края остаются в разметке `areaServed`. H1 и title главной и услуг без краёв, регион попадает в H1 только на странице региона.

## Почему

- Убрать края везде отвергнуто: пропадёт локальный сигнал для поиска, а страницы краёв станут сиротами.
- Оставить края в title и H1 услуг отвергнуто: это и есть «тулить куда попало», против прямой просьбы заказчика.
- Скрытый от глаз текст с краями отвергнут: это приём для поисковиков, а не разметка.
- JSON-LD выбран как место, где край виден роботу и не мешает посетителю.

## Последствия

- Запросы вида «ремонт электрики + край» страницы услуг не закрывают: их обслуживают только страницы краёв.
- Список краёв в данных остаётся один. Шаблоны обязаны выводить его только в разрешённых местах, общий подвал им наполнять нельзя.
- Правило ловится только проверкой названий краёв на собранных страницах. Новый блок может нарушить его незаметно.
